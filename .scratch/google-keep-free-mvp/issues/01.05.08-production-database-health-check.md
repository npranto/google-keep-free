# 01.05.08: Production database health check

**Status:** open
**Lane:** Standard (a new public route and a change to what the production smoke run proves)
**Parent:** ✅01.05-vercel-deploy.md
**Blocked by:** None
**Unblocks:** None

## Purpose

Prove the Production database credential works on every deploy without a signed-in test account, so a rejected `DATABASE_URL` is caught by the smoke run and not by a person loading the page. See `docs/incidents/0001-production-database-credential-rejected.md`.

## Scope

- A route (for example `app/api/health/route.ts`) that runs `select 1` through `lib/db` and returns only a status code and `{ ok: true }` or `{ ok: false }`. No credentials, host names, row counts or error text in the body or the logs' response.
- A `@smoke` E2E test that requests it, so `E2E (production)` fails when the database refuses the credential.
- The verification skill's feature map and the release card's wording: the first read of a database-backed page on Production is named as covered by this check.
- Settle at scope-check: whether the route needs rate limiting or can stay public (it does one cheap query), and whether it should also run once on the Vercel build so a bad credential stops the deploy.

## Out of scope

A signed-in test account on Production, uptime monitoring or alerting, feature flags, and any change to `lib/env.ts`.

## Acceptance criteria

- [ ] With a valid `DATABASE_URL` the route returns 200 and `{ ok: true }`.
- [ ] With a credential Neon rejects, the route returns 503 and `{ ok: false }`, with no error text or connection detail in the response.
- [ ] The production smoke E2E calls the route, and fails when it returns anything other than 200.
- [ ] The route is not under the auth guard, and it reads no Owner data.

## Testing expectations

An integration or route test for both outcomes, and the `@smoke` E2E. Prove the failing case by running the route against a wrong password locally, and record that a deploy with the old credential would have failed `E2E (production)`.
