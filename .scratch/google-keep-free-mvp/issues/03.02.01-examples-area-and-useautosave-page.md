# 03.02.01: Key-gated `/examples` area and the `useAutosave` checklist page

**Status:** implemented
**Lane:** Standard (a new access gate and a new optional secret, on an internal route)
**Parent:** 03.02-use-autosave-hook.md
**Blocked by:** 03.02 (the hook it exercises; both ship in PR #78)
**Unblocks:** None

## Purpose

Let the author try the `useAutosave` hook by hand, in a real browser, before 03.03 gives it a real screen. An internal `/examples` area holds pages for trying hooks and components, and its first page is a checklist of cases: each case has its own editor, and its steps tick by themselves as the visitor does them. A case passes when its last step ticks. Demo text and a fake server only.

## Scope

- `app/examples/` (layout, index page, `actions.ts`) and `lib/examples/access.ts`: the gate. No `EXAMPLES_ACCESS_KEY` means the whole area answers 404. With a key and no valid cookie, only a key form shows. A right key sets an 8-hour httpOnly cookie that holds a signature derived from the key, never the key.
- `lib/env.ts` and `.env.example`: `EXAMPLES_ACCESS_KEY`, optional, at least 24 characters when set.
- `app/examples/use-autosave/page.tsx` and `components/examples/use-autosave/`: 15 cases, each with its own editor and fake server, a "Save takes" selector per case, "Start over" per case and "Start all over" for the page. A case stops with a red message if the hook starts a save while another is running, or sends text the server already has.
- `docs/architecture/system.md`: a paragraph on the area.

## Out of scope

Real data, the real `updateNote` action, any user-facing link to the area, search indexing (the layout sends `noindex`), rate limiting of the unlock form, and UI or E2E tests of the page.

## Acceptance criteria

- [x] With no `EXAMPLES_ACCESS_KEY` set, `/examples` and `/examples/use-autosave` answer 404.
- [x] With a key set and no valid cookie, the visitor sees only the key form, with none of the page's text in the response. A wrong key shows "That key is not right."; the right key opens the examples index. Changing the key logs everyone out.
- [x] `/examples/use-autosave` shows 15 cases, each with its own editor. Steps tick by themselves as the visitor does them, and a case shows Passed when its last step ticks. There is no manual Passed control.
- [x] Each case has a "Save takes" selector and a "Start over" button. The page shows how many cases passed, and "Start all over" resets every case.
- [x] A case stops with a red message instead of passing when the hook starts a save while another is running, or sends text the server already has.
- [ ] Case 5 (switching tabs) passes after a real tab switch in a real browser.
- [x] `EXAMPLES_ACCESS_KEY` unset or empty is valid; set, it needs at least 24 characters.
- [x] The page holds at 390 and 1440 wide with no horizontal scroll.

## Testing expectations

- Unit tests of the pure step logic in `components/examples/use-autosave/cases.ts` (`cases.test.ts`, 8 tests): a scripted walkthrough of a case, the two hook promises, and a case that must not pass.
- No UI or E2E tests of the page, by choice: it is internal, and `docs/architecture/system.md` says so.
- The gate is proven on a production build with a throwaway key (404 closed, form when locked, wrong key refused, right key opens). The 15 cases are walked in a real browser by `/ns-to-verify local`, and case 5 needs a real tab switch.

## Decisions

- 2026-10-31: **Kept in PR #78 as a sub-ticket of 03.02**, not split into its own PR. The work was built on the 03.02 branch at the author's request and carries no ticket of its own until now. The user asked to carry on from PR #78 as it stands. Rejected: a hook-only PR plus a stacked examples PR (the pushed branch would need rewriting, a force-push).
- Protection is surface-level by design (see `docs/architecture/system.md`): closed by default, every page checks access itself because a page renders in parallel with its layout, and pages hold only demo text and fake data.

**Open, raised at scope-check on 2026-10-31, not yet answered:**

- What an invalid `EXAMPLES_ACCESS_KEY` should do. Today it fails the shared env check, which also fails the build's `prebuild` DB check before any deploy (ran: exit 1 with "must be at least 24 characters"), so a bad key cannot reach running production. Options: A keep fail-fast and add "24+ characters, no `$`" to `.env.example` (a `$` in `.env.local` is cut short by Next's dotenv-expand); B validate the key only in `lib/examples/access.ts`; C treat an invalid key as closed.
- Accept or fix two abuse gaps: no rate limit on the unlock form, and a stolen cookie works until the key is changed.
