# 03.03: Edit a Note in a dialog

**Status:** open
**Lane:** Standard (the first dialog, and the shared file that tickets 04 to 10 fill in)
**Parent:** 03-edit-a-note-with-autosave.md
**Blocked by:** 03.01, 03.02
**Unblocks:** 04

## Purpose

An Owner can click a Note, edit its title and body in a dialog with no Save button, see
"Saving…" then "Saved", and find the edit still there after a reload.

## Scope

- `components/notes/NoteEditorDialog.tsx`: a centered `Dialog` with title and body fields and an
  empty toolbar shell. It wires `useAutosave` (03.02) to `updateNote` (03.01), flushes on blur
  and on close, and keeps the Note's current `version` from each save's result.
- The shadcn `Dialog` primitive in `components/ui` (not installed yet).
- `components/notes/NoteCard.tsx`: clicking a card opens the dialog.
- A `role`-correct `aria-live="polite"` status region showing "Saving…" and "Saved" (fades after
  about 2s).
- Loading the full Note. `NoteCardData` carries only a 500-character `preview`, so the dialog
  cannot edit from it. Open for scope-check: pass the full body to the client, or fetch it when
  the dialog opens.
- E2E: open a Note, edit, wait for "Saved", reload, the edit persisted.

## Out of scope

The version-conflict banner (04), the pin, color, label, archive and trash toolbar buttons, the
read-only variant for a Trashed Note, a full-screen layout on mobile (14).

## Acceptance criteria

- [ ] Clicking a Note card opens the dialog with its current title and body, including a body
      longer than the card preview.
- [ ] Typing stops for 1s, the status shows "Saving…" then "Saved", and "Saved" fades after about
      2s.
- [ ] Blurring a field, closing the dialog, or hiding the tab flushes immediately.
- [ ] Closing and reopening, or refreshing, shows the saved content, and the grid card shows it
      too.
- [ ] The dialog traps focus, closes on Escape, and returns focus to the card.

## Relevant spec sections

"Edit / autosave a Note" journey; Autosave section (Status feedback); UI/UX §16, §7.

## Architecture/design constraints

`NoteEditorDialog.tsx` becomes the second hottest shared file (the toolbar fills in over 04, 05,
06, 07, 09, 10), the same sequential-chain reasoning as `NoteCard.tsx`. Keep the toolbar an
obvious slot so those tickets add to it without reworking the dialog.

## Testing expectations

E2E (Playwright, signed in as the test Owner): edit and reload; a body longer than the preview
opens in full; Escape closes and the edit is saved. Accessibility: the dialog and the live
region are named and announced (an axe check, as the repo already runs). The hook and the action
are covered by 03.02 and 03.01.

## Demo instructions

Open a Note, edit the title and body, watch the status region, stop typing, confirm "Saved",
refresh, and the edit persisted.

## Likely files/areas

`components/notes/NoteEditorDialog.tsx`, `components/ui/dialog.tsx`,
`components/notes/NoteCard.tsx`, `lib/notes/queries.ts` or `lib/notes/card.ts` (the full body),
`e2e/`.

## Risks / conflict hotspots

The full-body decision touches the shape the grid is built on (`NoteCardData`, `NoteGrid`).
Closing the dialog while a save is in flight must not lose the queued edit. The grid must show
the new content after a save without a manual refresh.

## Comments

- 2026-10-29: created by splitting 03 (user approved the 3-leaf split). Phase 1 of
  `/ns-flow-ticket`. The full-body gap was found while sizing: the ticket did not mention that
  cards carry only a preview.
- 2026-10-30 (from the 03.01 review): every successful save calls `revalidatePath("/")`, so the
  grid under the open dialog re-renders and moves the Note to the top while the Owner types.
  The dialog must keep its own `version` from each save's result, never from grid props. If the
  re-render proves costly or jarring, revalidate only on flush or close. `updateNote` can
  return `validation` with a raw zod message (for example for a bad `version`), so the status
  region should show a generic message for validation errors it did not author. An update that
  leaves both fields empty is rejected by design, so the dialog must show that failure.
