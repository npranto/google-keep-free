# 02.03.02: Composer

**Status:** closed
**Lane:** Standard (the first Client Component to call a Server Action, and the first kept E2E journeys that write Notes)
**Parent:** ✅02.03-composer-and-notes-grid.md
**Blocked by:** 02.03.01
**Unblocks:** 03

## Purpose

An Owner can click "Take a note...", write a Note, close the composer, and see the Note in
the grid, including after a full refresh.

## Scope

- `components/notes/Composer.tsx`: client component. Collapsed single-line "Take a note..."
  field that expands in place into a title field and an auto-growing body textarea with a
  Close button. Closing (blur outside the composer, Escape, Close) calls `createNote` when
  there is content, and writes nothing when both fields are empty. Always creates Active.
  It reuses the constants from `lib/notes/validation.ts` for `maxLength` only.
- `app/(app)/page.tsx`: the composer above the grid. The existing `EmptyState` shows under
  the composer when there are no Notes.
- E2E: a spec that creates a Note and reloads, and one that opens and closes an empty
  composer. Edit `e2e/shell.spec.ts` to assert the composer (02.03.01 already changed it to
  accept the grid or the empty state, because the shared test Owner always has Notes).

## Out of scope

Editing a Note, autosave, pin, color, labels, archive, trash, toolbar icons, `loading.tsx`,
`error.tsx`, a visual limit counter (the server enforces limits).

## Acceptance criteria

- [x] Typing into the composer and closing it with content creates an Active Note that
      appears in the grid.
- [x] Closing an empty composer performs no database write and shows no new card.
- [x] After a full page refresh, the created Note is still in the grid.
- [x] The composer looks right on desktop width, in light and dark.

## Testing expectations

E2E (Playwright, signed in as the test Owner): create-then-reload, and empty close. Notes
get a unique title per run and are not cleaned up (see Decisions). The composer's
validation errors have no screen yet, so nothing more is kept.

## Demo instructions

Sign in, click "Take a note...", type a title and body, click elsewhere to close, refresh
the page, and the Note still shows.

## Decisions

### How do E2E tests treat the shared test Owner's Notes? (2026-10-13, user)
- **Pick:** A. Tests create Notes with a unique title and never clean up. The shell test asserts the composer instead of the empty state. Once tickets 07 and 08 exist, tests clean up through the UI.
- **Rejected:** B, giving CI the Preview `DATABASE_URL` (a new secret and a second database route). C, a fresh Clerk Owner per test (about 40 lines of fixture code and orphan rows).
- **Evidence:** the preview E2E job has no `DATABASE_URL` and there is no delete feature yet (measured).
- **Principle:** delay machinery until the cost is real.
- **Undo:** trivial, test-only.

### Composer save trigger (2026-10-16, user approved after scope-check)
- **Pick:** a client component with one shared `close()` that calls `createNote` in a transition, from blur (guarded by `relatedTarget`), Escape and Close. Whitespace-only counts as empty and writes nothing.
- **Rejected:** a `<form action>` with `useActionState`, because the save is not tied to a submit and blur/Escape would have to fake one. URL-driven expansion (`?compose=1`), because every expand becomes a navigation.
- **Principle:** deep modules (one `close()` hides save, guard and reset; ticket 03 autosave reuses the shape).
- **Undo:** trivial, one component.

### Composer failure path (2026-10-16, user)
- **Pick:** A. When `createNote` returns `ok: false` or throws, the composer stays open with the text intact and shows the message in a `role="alert"` line.
- **Rejected:** B, collapsing and dropping the text, because a failed save would lose the Note with no signal.
- **Principle:** fail loudly, never lose user input.

### Review finding B5, blur-save failure leaves focus outside (2026-10-16, user)
- **Pick:** accepted as is. A failed save after a blur close leaves the composer open with the text and the `role="alert"` message; focus stays where the user clicked.
- **Rejected:** refocusing the title field, because it steals focus from something the user deliberately clicked.
- **Principle:** do not fix a rare edge case with a behavior that hurts the common one.
- **Flips when:** ticket 03 adds autosave with retry.
