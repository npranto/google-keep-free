# 01.02.01.03: About page UI (static, dummy content)

**Status:** done
**Parent:** 01.02.01-neon-account-and-database-url.md
**Blocked by:** None (01.01 is done; needs no credentials or integrations)
**Unblocks:** None (parallel with 01.02.01.01 and 01.02.01.02)

## Purpose

Show what a visitor sees when learning about the product, as a standalone page with
placeholder content.

## Scope

A new route `/about` (`app/about/page.tsx`) rendering a static about page: heading,
short tagline, a "Our story" section, a short "What we value" list of three or four
items, and a small "Meet the team" section with a few dummy team members (name, role,
placeholder avatar such as initials). Built from the existing shadcn/ui baseline
(reusing existing primitives; add others only if needed). Centered, readable layout
using Tailwind, visually consistent with the sign-up and sign-in pages
(01.02.01.01, 01.02.01.02). Dummy copy only.

## Out of scope

Real content or copy, images or asset uploads, CMS or data fetching, forms, auth or
Clerk, database, `/api/*` handlers, navigation or header/footer changes, linking the
page from anywhere else, and responsive tuning beyond a sensible default.

## Acceptance criteria

- [ ] `/about` renders the heading, tagline, "Our story" section, values list, and
      "Meet the team" section with dummy members.
- [ ] All content is hard-coded dummy data; no network calls.
- [ ] Any links or buttons present are inert (no navigation).
- [ ] The page is its own route; no other existing route or layout changes.
- [ ] No new env vars, no `/api/*` handlers, no auth or DB dependencies.
- [ ] Lint, typecheck and build pass.

## Demo / verification

Run the dev server, open `/about`, and inspect it visually, checking pixel-level
alignment, spacing and typography against the sign-up and sign-in pages.

## Review budget / risk

Small, about 10 minutes. Low risk since it is isolated to one new route.

## Comments

- Implemented `app/about/page.tsx` as a static server component matching the
  sign-up/sign-in card style. Vertical centering was intentionally dropped
  (unlike the auth pages) since the content is much taller and would clip
  off the top of the viewport otherwise; horizontal centering and spacing
  scale are kept consistent.
- Verified via `tsc --noEmit`, `npm run lint`, `npm run build`, and visual
  checks (chrome-devtools-axi) at desktop and mobile widths - no console or
  network errors, no navigation, no data fetching.
- Independent review (spec, standards, bug/security, simplicity) found no
  blocking issues.
- Added a `typecheck` npm script and pointed `.github/workflows/healthcheck.yml`
  at it instead of calling `tsc` directly, for consistency between local and CI.
