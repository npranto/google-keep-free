# 01.05.05: E2E runs in CI on real deployments

**Status:** closed
**Lane:** Standard (CI config that reads existing secrets; nothing creates or changes one)
**Parent:** 01.05-vercel-deploy.md
**Blocked by:** 01.05.04
**Unblocks:** 01.05.06

## Purpose

CI builds the app a second time inside `healthcheck.yml` and tests that copy. Test the
real deployments instead: the whole suite on every preview, the `@smoke` tests on
production after every production deploy. Item 5 of 7.

## Scope

- `.github/workflows/e2e.yml`, copied from
  `~/.claude/skills/ns-to-quality-check/workflows/e2e.yml` and adapted (Node 24, npm).
  - **E2E (preview):** the whole suite, on every successful `Preview` deployment.
  - **E2E (production):** the `@smoke` tests on `https://gfk.lol` (repository variable
    `PRODUCTION_URL`), on every successful `Production` deployment.
- Remove the `e2e` job from `healthcheck.yml`.
- Update `docs/agents/workflow.md`: the E2E line points at the workflow.

## Out of scope

Making `E2E (preview)` a required check (a branch protection change, the owner's step),
creating or changing any secret or variable, a production test account, and removing any
secret.

## Acceptance criteria

- [x] `E2E (preview)` is green on a real preview deployment of this PR.
- [x] It goes red once on a deliberate failure, and green again after the failure is removed.
- [x] `E2E (production)` is green on `https://gfk.lol` after the merge.
- [x] The preview job passes `CLERK_SECRET_KEY`, `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` and
      `E2E_CLERK_TEST_EMAIL`, and not `DATABASE_URL`.
- [x] Tracing is off in both jobs.
- [x] The bypass header goes only to the deployment's own origin (01.05.04's fixture).
- [x] `healthcheck.yml` no longer builds the app for E2E.
- [x] Repository secrets that end up unused are listed. None is deleted.

## Demo / verification

CI runs: preview green, preview red on a scratch commit, preview green after it is
reverted, then production green on the merge commit. Wall time of the PR before and after.

## Review budget / risk

Small: 3 files. The template has never run anywhere, hence the red-then-green proof.

## Decisions

### Does the production job get the bypass secret?

**Pick:** no. The production job gets no secret at all.

**Rejected:** passing it as the template does. `gfk.lol` is public and the `@smoke` tests
need no account, so the secret would sit in a job that does not use it.

**Evidence:** *measured*: the `/try-out` and redirect tests run signed out. The template's
`E2E_EXPECT_COMMIT` is dropped for the same kind of reason: the app does not expose its
commit, so nothing reads it.
**Principle:** least privilege.
**Undo:** trivial, one workflow edit.
**Decided by:** user, approved on the design card.
