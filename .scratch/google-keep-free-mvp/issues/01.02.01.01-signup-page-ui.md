# 01.02.01.01: Sign-up page UI (static, dummy content)

**Status:** in-progress
**Parent:** 01.02.01-neon-account-and-database-url.md
**Blocked by:** None (01.01 is done; needs no credentials or integrations)
**Unblocks:** None (01.03 may later replace or wrap this UI with Clerk)

## Purpose

Show what a customer sees when signing up, as a standalone page with placeholder content.

## Scope

A new route `/sign-up` (`app/sign-up/page.tsx`) rendering a static sign-up form UI: heading,
short tagline, name, email and password fields, a "Create account" button, and a "Already
have an account? Sign in" link (inert). Built from the existing shadcn/ui baseline
(reusing `Button`; add other primitives such as `Input` and `Label` only if needed).
Centered, readable layout using Tailwind. Dummy copy only.

## Out of scope

Form submission, validation, auth or Clerk, database, `/api/*` handlers, social login
buttons, sign-in page, redirects, responsive tuning beyond a sensible default, and
linking the page from anywhere else.

## Acceptance criteria

- [ ] `/sign-up` renders the heading, tagline, name, email and password fields, and a
      "Create account" button.
- [ ] Submitting or clicking the button does nothing (no network calls, no navigation).
- [ ] The "Already have an account? Sign in" link is present but inert.
- [ ] The page is its own route; no other existing route or layout changes.
- [ ] No new env vars, no `/api/*` handlers, no auth or DB dependencies.
- [ ] Lint, typecheck and build pass.

## Demo / verification

Run the dev server, open `/sign-up`, and inspect it visually, checking pixel-level
alignment, spacing and focus states on each field. Confirm nothing happens on submit.

## Review budget / risk

Small, about 10 minutes. Low risk since it is isolated to one new route. Keep the form
markup simple so the Clerk work in 01.03 can swap it out cleanly.
