# 02.03.05: Composer save-failure test

**Status:** closed

**Blocked by:** None

## Purpose

The composer keeps your text and shows an error when a save fails, so a Note is never lost silently (02.03.02 "Decisions", the failure path). That rule has no kept test, so it can regress without anyone noticing. Filed from the 02.03.02 quality check and review.

## Scope

- A test that makes `createNote` fail and checks that the composer stays open, the typed text is still there, and the message appears in the `role="alert"` line.
- Settle the seam at scope-check: a browser test that intercepts the Server Action response, or a component test. A component test needs a DOM test environment (jsdom and Testing Library) that the repo does not have, which is a new dependency decision.

## Out of scope

Changing the composer's behavior, other component tests, and the blur-save focus behavior accepted in 02.03.02 (review finding B5).

## Acceptance criteria

- [x] A kept test fails if the composer collapses, or drops the typed text, after a failed save.
- [x] The test is deterministic: no real network failure, no sleeps, no shared state.
- [x] The existing composer E2E journeys still pass.

## Testing expectations

The test is the deliverable. Seen failing for the intended reason where that is cheap (temporarily make the composer collapse on failure and watch it go red).

## Decisions

- 2026-10-26: the seam is a browser test in `e2e/composer.spec.ts` that aborts the `createNote` Server Action request (`page.route`, matched on POST with a `next-action` header). It adds no dependency; a component test would have needed jsdom and Testing Library for one test. The test counts the aborted calls, so it cannot pass without a failed save. Seen red by making the composer's catch path call `reset()`.
