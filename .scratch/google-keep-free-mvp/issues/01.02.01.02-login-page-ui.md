# 01.02.01.02: Login page UI (static, dummy content)

**Status:** ready-for-agent
**Parent:** 01.02.01-neon-account-and-database-url.md
**Blocked by:** None (01.01 is done; needs no credentials or integrations)
**Unblocks:** None (01.03 may later replace or wrap this UI with Clerk; parallel with 01.02.01.01)

## Purpose

Show what a returning customer sees when logging in, as a standalone page with placeholder content.

## Scope

A new route `/sign-in` (`app/sign-in/page.tsx`) rendering a static login form UI: heading,
short tagline, email and password fields, a "Sign in" button, a "Forgot password?" link
(inert), and a "New here? Create an account" link (inert). Built from the existing
shadcn/ui baseline (reusing `Button`; add other primitives such as `Input` and `Label`
only if needed). Centered, readable layout using Tailwind, visually consistent with the
sign-up page in 01.02.01.01. Dummy copy only.

## Out of scope

Form submission, validation, auth or Clerk, database, `/api/*` handlers, social login
buttons, password reset page, redirects, responsive tuning beyond a sensible default,
and linking the page from anywhere else.

## Acceptance criteria

- [ ] `/sign-in` renders the heading, tagline, email and password fields, and a
      "Sign in" button.
- [ ] Submitting or clicking the button does nothing (no network calls, no navigation).
- [ ] The "Forgot password?" and "New here? Create an account" links are present but inert.
- [ ] The page is its own route; no other existing route or layout changes.
- [ ] No new env vars, no `/api/*` handlers, no auth or DB dependencies.
- [ ] Lint, typecheck and build pass.

## Demo / verification

Run the dev server, open `/sign-in`, and inspect it visually, checking pixel-level
alignment, spacing and focus states on each field. Confirm nothing happens on submit.

## Review budget / risk

Small, about 10 minutes. Low risk since it is isolated to one new route. Both this and
01.02.01.01 may add `Input` and `Label` primitives, so expect a merge conflict on those
files if run in parallel; whichever merges second should reuse the first's versions.
