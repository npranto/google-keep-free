# 01.05.07: Versioning carries the bump

**Status:** closed
**Lane:** Standard (release config that tags and publishes on every merge to `main`)
**Parent:** 01.05-vercel-deploy.md
**Blocked by:** 01.05.06
**Unblocks:** None

## Purpose

`release.yml` tags every merge but leaves `package.json` at 0.1.0 while the newest tag is
v0.2.9, so the tag is the only record of the version. Make each PR carry the version it
releases as, so the tagged commit contains its own version. Item 6 of 7.

## Scope

- Replace `.github/workflows/release.yml` with `~/.claude/skills/ns-to-deploy/workflows/release.yml`,
  keeping `branches: [main]` (the template says `[main, master]`) and `INITIAL_VERSION: "0.1.0"`.
- `package.json` and `package-lock.json` (two places) hold the version this PR releases as,
  in its own commit `chore(release): vX.Y.Z`.
- The README "Releases" section stops saying the tag is the only record. The codebase map's
  CI line says where the version comes from.

## Out of scope

`rollback.yml` (identical to its template except two input descriptions), any change to the
bump rules, and any tag created by hand.

## Acceptance criteria

- [x] `release.yml` matches the template except for `branches: [main]`.
- [x] `package.json` and both version fields of `package-lock.json` say the version this PR
      releases as, and it is newer than the newest tag.
- [x] The README "Releases" section no longer says the tag is the only record, and says a
      PR carries its own bump.
- [x] (log line read, summary table not read directly: see closing notes) After the merge, the Release run is green, its summary shows "Version from" =
      `package.json` and "package.json matches" = yes, and the tag points at the merge
      commit.

## Demo / verification

The Release run on the merge commit, and `git show vX.Y.Z:package.json` holding that version.

## Review budget / risk

Small: 5 files. A mistake here mis-tags a release, so the version is checked again on the
release card.
