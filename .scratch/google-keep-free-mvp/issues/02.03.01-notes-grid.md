# 02.03.01: Notes grid

**Status:** in-progress
**Lane:** Standard (new shared components `NoteCard` and `NoteGrid`, used by every later view)
**Parent:** 02.03-composer-and-notes-grid.md
**Blocked by:** 02.02.03
**Unblocks:** 02.03.02

## Purpose

The home page shows the Owner's Active Notes as a read-only masonry grid of cards, and still
shows the empty state when there are none.

## Scope

- `components/notes/NoteGrid.tsx` and `NoteCard.tsx`: Server Components, read-only. Title
  and body preview, CSS multi-column masonry per `ui-spec.md` section 12 (`column-count` +
  `break-inside: avoid`, 4 columns on desktop), 1px border, no toolbar.
- `app/(app)/page.tsx`: calls `getActiveNotes()` and maps each row to the card-sized shape
  (id, title, a body preview, color, pinned) so the full `body` and the Owner id never reach
  a Client Component. Renders the existing `EmptyState` when there are no Notes, and
  `NoteGrid` otherwise. Where the mapping lives (the page or a small module with a unit
  test) is decided at scope-check.

## Out of scope

The composer, any way to create a Note in the UI, editing, pin, color, labels, archive,
trash, toolbar icons, `loading.tsx`, `error.tsx`, tablet and mobile column counts beyond
what the CSS gives for free (ticket 14).

## Acceptance criteria

- [ ] With Active Notes in the database, the home page shows one card per Note with its
      title and body preview, and the Notes are in the order `getActiveNotes()` returns.
- [ ] With no Active Notes, the home page still shows the empty state.
- [ ] No full `body` or `ownerId` is passed to a Client Component or appears in the page's
      payload beyond the preview.
- [ ] The grid and cards look right on desktop width, in light and dark.

## Testing expectations

The behavior is a read of rows the caller cannot yet create through the UI, so the proof is
local: insert Notes for the test Owner, load the page, screenshot light and dark. A unit
test covers the card mapping (preview truncation, empty title, empty body). The E2E journey
that creates a Note and sees it lands in 02.03.02, where a Note can be created.

## Demo instructions

Insert a Note for your Owner in the dev database, run the app, sign in, and the card shows
on the home page after a refresh. With no rows, the empty state shows.

## Decisions

### Where does the card projection live? (2026-10-14, user)
- **Pick:** A. A pure `toNoteCard(row)` in `lib/notes/card.ts` with a unit test, called by the page. `NoteGrid` only accepts the card shape, so a raw row (which has no `preview`) cannot compile into it. `queries.ts` is untouched.
- **Rejected:** B, a SQL projection (`getActiveNoteCards()` with `left(body, N)`), because it needs a card variant per view and new integration tests on authorization code with no measured need (0.171 ms for 100 Notes). C, truncating inside `NoteCard`, because full rows would reach every card and the guard disappears once the card becomes a Client Component in ticket 03.
- **Principle:** design it twice.
- **Flips when:** a page shows hundreds of long Notes, or search (ticket 13) reads many bodies. Then move the truncation into SQL.
- **Undo:** trivial, one module and its callers.

### Trim `color` and `pinned` from the card shape? (2026-10-14, user)
- **Pick:** keep them. The card shape is `{ id, title, preview, color, pinned }`, as the 02.02.03 comment suggested, even though nothing renders `color` or `pinned` until tickets 09 and 05.
- **Rejected:** the trim (`{ id, title, preview }`), which scope-check recommended because the two fields are unused here.
- **Principle:** smallest change that solves it (declined by the user).
- **Undo:** trivial.

### `e2e/shell.spec.ts` asserts the grid or the empty state (2026-10-14, user)
- **Found by:** the local proof. Scope-check's "safe because the test Owner has no Notes" was wrong (traced, never ran): the shared test Owner already had 3 Notes (`E2E <timestamp> ...`, left by earlier runs), so the empty-state assertion failed (measured, `npx playwright test e2e/shell.spec.ts`).
- **Pick:** the test passes when either the `Notes` list or the empty state shows, and is renamed to "the Notes area". The 3 rows are left alone.
- **Rejected:** deleting the 3 rows (they are not this ticket's and the next ticket's tests would create more), and dropping the Notes assertion (the page area would be unasserted).
- **Principle:** know the blast radius.
- **Undo:** trivial, test-only. 02.03.02 replaces the assertion with the composer.

### Cards use `h2` with no page `h1` (2026-10-15, review N3, left by the agent's recommendation)
- **Pick:** leave. The page heading is defined in ui-spec section 19 but no ticket renders it yet, and adding one here is beyond this ticket's scope.
- **Flips when:** a ticket adds the page heading, which then needs to be an `h1`.

### Production read of `notes` is unproven (2026-10-14, agent, carried as a check)
- `/` now reads `notes` on every signed-in load. Production was migrated by hand and not verified by the agent, and production has no E2E test account.
- **Check:** at the release stop the user loads https://gfk.lol signed in, and `ns-to-observe` checks 5xx and runtime errors.
