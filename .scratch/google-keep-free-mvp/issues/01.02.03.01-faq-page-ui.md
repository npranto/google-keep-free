# 01.02.03.01: FAQ page UI (static, dummy content)

**Status:** in-progress
**Parent:** 01.02.03-drizzle-neon-client-select-1.md
**Blocked by:** None (needs no credentials, integrations or database)
**Unblocks:** None

## Purpose

Show what a visitor sees when looking for answers to common questions, as a
standalone page with placeholder content.

## Scope

A new route `/faq` (`app/faq/page.tsx`) rendering a static FAQ page: heading, short
tagline, and a list of five or six dummy question and answer pairs. Built from the
existing shadcn/ui baseline (reusing existing primitives; add others only if needed).
Centered, readable layout using Tailwind, visually consistent with the existing
`/about`, sign-up and sign-in pages. Dummy copy only.

## Out of scope

Real content or copy, images or asset uploads, CMS or data fetching, search or
filtering, forms, auth or Clerk, database, `/api/*` handlers, navigation or
header/footer changes, linking the page from anywhere else, and responsive tuning
beyond a sensible default. The existing `/about` page is not changed in behavior,
content or markup.

## Added during quality-check

The repo had no format check, a missing core check. Added in this PR: Prettier as a
dev dependency, `format` and `format:check` scripts (scoped to `app`, `components`,
`lib`), and a `format` job in `.github/workflows/healthcheck.yml`. Five existing files
were reformatted with whitespace-only changes: `app/about/page.tsx`,
`lib/db/index.ts`, `lib/db/schema.ts`, `lib/db/check-connection.mts` and
`lib/env.test.ts`. Docs and `.scratch` markdown are not covered by the check.

## Acceptance criteria

- [ ] `/faq` renders the heading, tagline, and five or six dummy question and answer
      pairs.
- [ ] All content is hard-coded dummy data; no network calls.
- [ ] Any links or buttons present are inert (no navigation).
- [ ] The page is its own route; no other existing route or layout changes in
      behavior, content or markup. `/about` receives whitespace-only formatting
      fixes from the new format check.
- [ ] No new env vars, no `/api/*` handlers, no auth or DB dependencies.
- [ ] Lint, typecheck and build pass.

## Demo / verification

Run the dev server, open `/faq`, and inspect it visually, checking pixel-level
alignment, spacing and typography against `/about`, sign-up and sign-in.

## Review budget / risk

Small, about 10 minutes. Low risk since it is isolated to one new route.
