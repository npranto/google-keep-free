# 02.02.01: Note validation schema and ActionResult

## Purpose

Give the server one place that says what a valid new Note is, and one shape for an
action to say "no". Nothing calls them yet, so this lands on its own.

## Scope

- `lib/notes/validation.ts`: Zod schema for create input (title at most 300, body at most
  20000, and not both empty, where whitespace-only counts as empty) and the limits as
  exported constants for the UI to reuse. Validate on the trimmed text, keep the input as
  typed, and count length on the raw text.
- `lib/shared/result.ts`: `ActionResult<T>` with the one error kind this slice needs,
  `validation`.
- `lib/notes/validation.test.ts`.

## Out of scope

Any action, query, database call, or UI.

## Acceptance criteria

- [ ] A title of exactly 300 and a body of exactly 20000 characters are accepted.
- [ ] A title of 301 or a body of 20001 characters is rejected.
- [ ] Empty title with empty body, including whitespace only, is rejected.
- [ ] A client-supplied `ownerId` is dropped from the parsed output.
- [ ] The limits are exported as constants, and `ActionResult<T>` has a `validation`
      error kind.

## Testing expectations

Unit: the schema at 300/301 and 20000/20001, empty and whitespace-only input, a stray
`ownerId`. Nothing is user-visible, so no E2E.

## Decisions

### How is "not both empty" checked, and is text trimmed? (2026-10-13, user approved the agent's pick)
- **Pick:** one `z.object` with a whole-object `.refine` that checks the trimmed title or body is non-empty. The text is kept as typed, and length is counted on the raw text.
- **Rejected:** storing trimmed text (it would fight the editor's autosave in 03). A separate `isEmpty()` helper (one use).
- **Evidence:** Zod 4 `z.object` strips unknown keys (inferred, tested here). Autosave sends what the user sees (inferred from the spec).
- **Principle:** parse, don't validate.
- **Undo:** trivial, it is code only.
