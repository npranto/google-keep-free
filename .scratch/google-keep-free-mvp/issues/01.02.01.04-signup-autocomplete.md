# 01.02.01.04: Add autocomplete attributes to sign-up form inputs

**Status:** done
**Parent:** 01.02.01-neon-account-and-database-url.md
**Blocked by:** None
**Unblocks:** None

## Purpose

Fix a minor accessibility/UX gap on the sign-up placeholder page: its `name`, `email`,
and `password` inputs have no `autocomplete` attribute, so browsers can't offer
autofill. Flagged by Chrome DevTools during `01.02.01.03`'s integration-check.
`/sign-in` already has this set correctly and needs no change.

## Scope

In `app/sign-up/page.tsx`, add `autoComplete="name"` to the Name input,
`autoComplete="email"` to the Email input, and `autoComplete="new-password"` to the
Password input - matching the `current-password` vs `new-password` distinction already
used correctly on `/sign-in`.

## Out of scope

Any other change to the form, validation, submission behavior, or the sign-in page
(already correct).

## Acceptance criteria

- [x] All three `/sign-up` inputs have the `autocomplete` values above.
- [x] Chrome DevTools no longer flags missing autocomplete on `/sign-up`.
- [x] Lint, typecheck, build pass.

## Demo / verification

Open `/sign-up`, inspect each input's `autocomplete` attribute, confirm the DevTools
console warning is gone.

## Review budget / risk

Trivial, under 5 minutes. No risk - three attribute additions on a static placeholder
page already slated for eventual Clerk replacement.
