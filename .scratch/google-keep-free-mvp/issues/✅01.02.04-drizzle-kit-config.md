# 01.02.04: Drizzle Kit config

**Status:** closed
**Parent:** ✅01.02-env-validation-and-db-connection.md
**Blocked by:** 01.02.03
**Unblocks:** 01.03

## Purpose

Have the migration tooling configured and able to reach the database, so later tickets
can generate and apply migrations.

## Scope

`drizzle.config.ts` (schema path `lib/db/schema.ts`, out dir `lib/db/migrations`,
Postgres dialect, `DATABASE_URL`), `drizzle-kit` dev dependency, `db:generate` and
`db:migrate` npm scripts.

## Out of scope

Generating a real migration, tables, auto-running migrations in the Vercel build.

## Acceptance criteria

- [x] `drizzle.config.ts` loads with no errors.
- [x] `db:generate` against the empty schema reports nothing to migrate.
- [x] Migrations are never wired into the build.

## Demo / verification

Run `db:generate` and see the "nothing to migrate" result.

## Review budget / risk

Small. Risk: Drizzle Kit may prefer a direct (non-pooled) URL. Keep the single
`DATABASE_URL` and revisit only if this step fails.

## Comments

Implemented on `chore/01.02.04-drizzle-kit-config`. PR: https://github.com/npranto/google-keep-free/pull/23
Shipped: squash-merged into `main` as commit `58473bd`, live in production, health HEALTHY.

Approach: `drizzle.config.ts` imports the validated `env` from `lib/env.ts`, and the `db:*` scripts run drizzle-kit through `node --env-file=.env.local`, the same way `lib/db/check-connection.mts` loads env. Not raw `process.env` (vague error when unset) and not dotenv (extra dependency). No deviation from the ticket.

Known limits, accepted:
- `db:migrate` over the pooled Neon URL is untested because no migration exists yet. The first ticket that generates a migration should run it and, if it fails, revisit a direct (non-pooled) URL per the risk note above.
- `npm audit` reports an esbuild 0.18 advisory (GHSA-67mh-4wv8-2f99) through drizzle-kit 0.31.11, dev-only. `npm audit --omit=dev` is clean. Revisit when a newer stable drizzle-kit ships.
- `db:generate` writes an empty `lib/db/migrations/meta/_journal.json` even with no changes. It was not committed.
