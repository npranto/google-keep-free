# 02.02.02.01: Rename the vitest configs to .mts

**Status:** closed
**Lane:** Quick (two renames and two small edits, config only, no behavior change)
**Parent:** ✅02.02.02-create-note-action-and-integration-harness.md
**Blocked by:** none (02.02.02 is closed)
**Unblocks:** nothing

## Purpose

Stop every test run printing a Vite warning. `vitest.config.ts` and
`vitest.integration.config.ts` use ESM syntax in a package that Node reads as CommonJS,
which Vite says will stop working when its "native" config loading becomes the default.
First noted in the 01.05 close and never ticketed.

## Scope

- Rename `vitest.config.ts` to `vitest.config.mts` and `vitest.integration.config.ts` to
  `vitest.integration.config.mts` (`git mv`, one at a time).
- `package.json`: `test:integration` points at `vitest.integration.config.mts`.
- Fix the comment in the integration config that names `vitest.config.ts`.

## Out of scope

`"type": "module"` in `package.json` (it changes how every `.js` and `.ts` file is read:
Next, Clerk, Playwright, drizzle). Any other config file, the repeated `@` alias, and the
formatter's scope (`format:check` still covers only `app`, `components`, `lib`).

## Acceptance criteria

- [x] `npm test` and `npm run test:integration` print no `configLoader` or "ESM syntax in
      a file loaded as CommonJS" warning.
- [x] `npm test` still runs the same tests (37 in 5 files at the time of writing) and
      leaves the integration tests out, and `npm run test:integration` still runs its 8
      tests against the real database.
- [x] Typecheck, lint, format check and build pass, and the renamed configs are still
      type-checked (`tsconfig.json` already includes `**/*.mts`).
- [x] No file outside closed-ticket history still names `vitest.config.ts` or
      `vitest.integration.config.ts`.

## Testing expectations

No new tests. The proof is the existing suites and the missing warning, measured before
and after. The CI Healthcheck `test` job proves Vitest finds `vitest.config.mts` by
default. Nothing is user-visible, so no E2E.

## Risks

- Vitest not picking up a `.mts` config by default. Guess: it does (the documented names
  include `.mts`), and the CI `test` job proves it.
- The warning not going away on this Vite version. Measure it before the rename and after.

## Undo

Revert the PR. Config only, no data, nothing shipped to users.

## Decisions

### `.mts` or `"type": "module"`? (2026-10-14, proposed by agent, approved by the user at scope-check)
- **Pick:** `.mts`. The repo already uses it (`lib/db/check-connection.mts`), and `tsconfig.json` already includes `**/*.mts`.
- **Rejected:** `"type": "module"`, too wide for a warning. `.mjs`, which loses the types.
- **Evidence:** the warning text names both fixes (inferred), and the two references to the old filenames are in `package.json` and one comment (measured with a search).
- **Undo:** trivial, a rename.
