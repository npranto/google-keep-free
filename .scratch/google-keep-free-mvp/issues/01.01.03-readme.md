# 01.01.03: Craft a solid README.md from docs/

**Status:** ready-for-agent
**Parent:** 01.01-nextjs-scaffold-tailwind-shadcn.md
**Blocked by:** 01.01.01
**Unblocks:** None (can run in parallel with 01.01.02)

## Purpose

A root `README.md` that lets a new reader understand what the project is, how it is
built, and how to run it, without opening `docs/` first.

## Scope

Write `README.md` at the repo root, derived from `docs/` (source of truth stays in
`docs/`; the README summarises and links, it does not duplicate):

- Project pitch and MVP capabilities, from `docs/product/PROJECT_BRIEF.md`.
- Tech stack and architecture summary (Next.js App Router, Server Components for
  reads, Server Actions for writes, Neon Postgres via Drizzle, Clerk auth, Vercel),
  from `docs/architecture/system.md` and `docs/adr/`.
- Getting started: prerequisites, install, and the real `dev`, `build`, `lint`
  scripts from `package.json`.
- Project structure overview (only directories that exist at the time of writing).
- Documentation index linking `docs/product`, `docs/architecture`, `docs/design`,
  `docs/adr`, `CONTEXT.md`.
- Status/roadmap pointer to the MVP tickets under `.scratch/`.

## Out of scope

Editing anything under `docs/`, contributing guide, license selection, badges or
screenshots that require a deployed app, documenting env vars, DB or auth setup that
do not exist yet (link to the relevant ticket or doc instead).

## Acceptance criteria

- [ ] `README.md` exists at the repo root and every claim matches `docs/` and the
      current `package.json`.
- [ ] Commands in "Getting started" work when run verbatim on a fresh clone.
- [ ] All relative links resolve to existing files.
- [ ] Features not yet built are clearly marked as planned, not presented as working.
- [ ] No em dashes; no content copied wholesale from `docs/` where a link suffices.

## Demo / verification

Render the README, click every link, and run the Getting started steps from a clean
clone.

## Review budget / risk

Docs only, single file. Risk: drift from `docs/` or from tickets still in flight
(01.01.02, 01.02+); keep future-facing sections short and link-based.
