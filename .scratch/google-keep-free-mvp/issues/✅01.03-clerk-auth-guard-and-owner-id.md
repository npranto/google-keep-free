# 01.03: Clerk auth guard and getOwnerId()

**Status:** closed
**Parent:** 01-application-foundation.md
**Blocked by:** 01.02
**Unblocks:** 01.04

## Purpose

Only signed-in visitors reach `(app)`, and server code derives the Owner solely from the
session.

## Scope

`ClerkProvider`, sign-in/sign-up routes, `(app)/layout.tsx` auth guard, Clerk vars added
to `lib/env.ts` and `.env.example`, `lib/auth/current-owner.ts` (`getOwnerId()`), smoke
test for the redirect.

## Out of scope

Shell UI, local user records, any Note data.

## Acceptance criteria

- [x] Visiting the app signed-out redirects to Clerk sign-in; no local user record is
      ever created.
- [x] Signed-in visit to `/` renders the placeholder page.
- [x] `getOwnerId()` throws/redirects if called with no session; never accepts a
      client-supplied id.
- [x] Smoke test confirms the guard redirects signed-out visitors.

## Demo / verification

Visit signed-out (redirect), sign in (land on `/`), run the smoke test.

## Review budget / risk

About 15 minutes. Risk: middleware/route matcher configuration.

## Comments

**Shipped** in PR #25 (`bbd7e80`), live at https://gfk.lol. Approach: `proxy.ts` only
reads the session (`clerkMiddleware()`); the `(app)` layout and every future Server
Action call `getOwnerId()`, which redirects to `/sign-in` without a session. Not
proxy-only protection (a matcher typo would expose pages) and not both (two copies of
one rule).

**Deviations from the ticket**
- The static sign-in and sign-up pages were replaced by Clerk's `<SignIn />` and
  `<SignUp />` on catch-all routes, as `docs/architecture/system.md` planned.
- Added `proxy.ts` (Clerk needs it for `auth()`) and `vitest.config.ts` (the `@/`
  alias for tested code).
- `drizzle.config.ts` and `lib/db` now need the Clerk keys in `.env.local` too, because
  `lib/env.ts` validates every variable in one schema.
- Production needed more than the ticket assumed: the first deploy returned 500 on
  every route (Clerk keys missing in the Production environment) and was rolled back
  within about 5 minutes. A live Clerk instance cannot use `*.vercel.app`, so the app
  now lives at `gfk.lol` with Clerk's DNS records and Google OAuth credentials.

**Deferred or open** (follow-up tickets to be written with `/ns-to-tickets`)

  there with `redirect_uri_mismatch`).
- Bump `next` 16.3.6 to 16.4.0 (existing high-severity advisory).
- Clerk production shows "Communication locked": email codes and password reset do not

- Nits left open from review: the sign-in path is written in two places

- `npm run format` only covers `app`, `components` and `lib`, not `proxy.ts` or
  `vitest.config.ts`.
